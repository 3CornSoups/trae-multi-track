# 面向专利数据挖掘与前沿技术研判的多智能体情报分析系统

> 本文档为论文方法章节可用的**系统方案叙事**，将多源科技情报采集、多轨定量分析、多智能体协同解释与可视化呈现统一为可复现的研究框架。系统本身不必完整工程落地，但其能力边界、方法分工与协作逻辑均可作为论文中的方法论表述。

---

## 1. 研究动机与系统定位

科技情报研究长期面临三类结构性矛盾：

1. **数据异构**：科学文献、专利文本、政策法规分属不同平台与许可机制，难以用单一接口贯通；
2. **方法异构**：主题发现、引文主路径、语义替代性、前沿指标判别等依赖不同算法范式，既有确定性程序，也有需语义理解的开放任务；
3. **解释异构**：定量结果往往以矩阵、路径、聚类标签形式存在，难以直接转化为面向决策的情报结论。

为此，本文提出一套**多智能体情报分析系统（Multi-Agent Intelligence Analytics System, MAIAS）**。其核心主张并非“用大模型替代全部分析方法”，而是：**把确定性算法固化为可调用资产，把语义判断与跨源解释交给角色化智能体，把可视化与报告生成交给协议化工具层**，从而在科学性、可复现性与叙事完整性之间取得平衡。

系统面向三类研究目标：

| 目标 | 情报问题 | 主要方法支撑 |
|------|----------|--------------|
| 专利数据挖掘 | 技术结构、演化主干、关键节点是什么 | 引文网络、SPC/Key-Route 主路径、c-TF-IDF 主题刻画 |
| 替代性分析 | 哪些路线在功能/场景上可替代，替代是否正在发生 | 语义相似度预筛+精判、功能—场景—原理三维可替代性、增长与主路径地位转移 |
| 前沿技术研究 | 哪些主题具有前沿特征，跨源证据是否一致 | 多特征融合向量化、聚类主题划分、前沿识别指标体系、政策—论文—专利三角验证 |

输入源覆盖**科学—政策—技术**三类情报对象：论文与项目数据、专利数据、政策与法规数据。

## 2. 总体架构：三层闭环

系统采用“**数据采集 → 多轨分析 → 协同解释与可视化**”三层闭环，辅以编排层（Orchestrator）与治理层（Hooks / 审计 / 知识库）。

```
用户研究意图 / 检索式 / 领域本体
            │
            ▼
┌───────────────────────────────────────────┐
│  L1 多源数据采集与治理层                   │
│  API · 爬虫 · 模拟点击 · 批量下载 · 用户导入 │
└───────────────────────────────────────────┘
            │ 标准化语料库 / 元数据仓 / 引文图
            ▼
┌───────────────────────────────────────────┐
│  L2 多轨分析执行层                         │
│  固定程序 · Skills · 本地小模型 · LLM API  │
└───────────────────────────────────────────┘
            │ 主题簇 / 主路径 / 相似度表 / 指标分
            ▼
┌───────────────────────────────────────────┐
│  L3 多智能体解释与可视化层                 │
│  角色智能体 · 冲突消解 · Draw.io MCP · 文生图 │
└───────────────────────────────────────────┘
            │
            ▼
     情报结论报告 / 可复核证据链
```

三层之间不是单向流水线，而是带反馈的闭环：L3 的解释冲突可触发 L2 重算（如调整相似度阈值）；L2 的数据缺口可触发 L1 补采；Hooks 在关键节点强制校验输出格式、引用完整性与许可合规。

## 3. L1 数据采集与治理层：按源匹配接入策略

### 3.1 设计原则

不同数据源在**开放程度、反爬强度、结构化程度、法律许可**上差异显著。系统因此采用“**一源一策**”：能 API 则 API，需检索交互则模拟点击，批量许可则下载，敏感或受限则用户提供并登记来源声明。

### 3.2 数据源—接入方式对照表

| 数据源 | 情报类型 | 推荐接入方式 | 典型用途 | 备注 |
|--------|----------|--------------|----------|------|
| **OpenAlex** | 论文/作者/机构/概念 | **开放 API** | 构建科学文献底座、学科概念映射、引用关系补全 | 适合大规模结构化拉取；作为论文侧主入口 |
| **arXiv** | 预印本全文与元数据 | **开放 API / OAI-PMH** | 前沿方法与未正式发表成果补充 | 适合 AI、神经科学等快速演进领域 |
| **Google Patents（BigQuery public datasets）** | 全球专利题录、引文、IPC | **BigQuery SQL 查询** | 专利全集抽样、引文边构建、IPC 统计 | 适合海量结构化检索；复杂条件用 SQL 固化为 Tool |
| **incoPat / 商业专利库** | 精标专利字段、同族、法律状态 | **批量数据下载 + 用户导入** | 高精度实验数据集、法律状态与同族分析 | 许可驱动；系统登记字段映射模板 |
| **CNKI** | 中文期刊/学位论文 | **模拟点击 + 受限爬取 / 用户导出** | 中文科学与应用研究证据 | 强反爬与授权约束；优先用户导出或机构接口 |
| **Overton** | 政策引用与政策文献 | **API（机构订阅）** | 政策对科学/技术的引用链条、政策注意力 | 用于政策侧验证前沿主题社会显著性 |
| **北大法宝等法规库** | 法规、规章、司法解释 | **模拟点击 / 机构接口 / 用户提供** | 合规约束、产业政策文本 | 法律文本常需人工确认版本效力 |
| **政府网站 / 部委政策库** | 产业政策、科技规划 | **定向爬虫 + 模拟点击** | 政策主题、任务清单、资助导向 | 页面结构多变，爬虫需 Skill 化维护 |
| **用户本地语料** | 项目书、内部报告、已清洗表 | **用户上传** | 补足商业库缺口、复现既有实验 | 强制元数据：来源、许可、时间戳 |

### 3.3 采集智能体与工具化封装

L1 由 **数据采集智能体（Data Ingestion Agent）** 统一调度，其下挂已注册 Tools：

- `tool.openalex.search`：API 直连；
- `tool.arxiv.fetch`：API/OAI；
- `tool.bigquery.google_patents`：参数化 SQL 模板（IPC、时间窗、引文深度）；
- `tool.cnki.session_export`：模拟登录与检索式驱动的导出流程（需人工会话票据）；
- `tool.policy.crawl`：政策站点定向爬虫；
- `tool.overton.query`：政策引用 API；
- `tool.user_upload.validate`：校验用户 CSV/Excel 字段完备性。

采集完成后进入**治理流水线**：去重、缺失值处理、公开号规范化、停用词与噪声字符清洗、时间窗切片（如训练/验证/测试或累积窗口 2000–2005 … 2000–2026），形成统一的**实验数据集与引文图仓库**。

## 4. L2 多轨分析执行层：方法—算力—封装形态的匹配

L2 是系统科学性的核心。原则是：**能确定性复现的绝不交给生成式模型临场发明；需要语义理解与开放判断的，才启用小模型或大模型 API。**

### 4.1 三条分析轨道

#### 轨道 A：前沿技术主题识别（多特征融合 → 聚类 → 指标判别）

**目的**：从项目、论文、专利多源文本中发现技术主题，并判别哪些主题具备前沿特征。

**方法链条**（对应论文固定分析流程）：

1. **关键词补全**：对缺失关键词的文献，由关键词抽取智能体按系统提示词抽取核心技术/方法词，严格 JSON 输出；
2. **多特征向量化**：
   - 标题+摘要 → `jina-embeddings-v3` → 语义特征向量；
   - IPC/学科分类号 → 同嵌入模型 → 分类特征向量；
   - 关键词 → Biterm Topic Model（BTM）→ 主题特征向量；
3. **融合与降维**：多特征融合向量 → UMAP；
4. **主题划分**：肘部法 + 轮廓系数选最优 \(K\) → K-means → c-TF-IDF 提取簇特征词；
5. **前沿判别**：将主题输入前沿技术识别指标体系，完成主题类型判定与结果验证。

**封装形态**：

| 步骤 | 封装 | 算力形态 | 理由 |
|------|------|----------|------|
| 关键词抽取 | 系统提示词 + Agent | 大模型 API | 术语规范性与结构化输出需要语义能力 |
| jina 嵌入 | 固定程序 / Tool | 远程嵌入 API 或本地服务 | 向量化是确定性变换 |
| BTM / UMAP / K-means / c-TF-IDF | 固定 Python 程序 | 本地 CPU/GPU | 可复现、可调参、适合消融实验 |
| 前沿指标计算 | 固定程序 + 指标配置 | 本地 | 指标体系应透明、可审计 |
| 主题命名与跨源对齐叙述 | Skill 触发编程智能体微调脚本 / LLM 摘要 | 混合 | 命名属于解释层，计算层保持稳定 |

#### 轨道 B：引文网络与主路径演化（技术主干与节点重要性）

**目的**：回答“技术沿哪条主干演化、哪些专利处于必经之路”。

**方法链条**：

1. 由专利题录与引文边构建有向无环（近似）引文网络；
2. 按累积时间窗切片（如 pre-2000、2000–2005、…、2000–2026）；
3. 计算边的 **SPC（Search Path Count）** 及对照指标 SPLC；
4. 采用 **Key-Route** 提取多条主路径，避免单路径丢失轨道分化；
5. 输出路径节点、边权重、时期对比，支撑后续替代性与安全暴露度分析。

**封装形态**：整条轨道以**固定程序库**为主（`mainpath.spc`、`mainpath.keyroute`），由分析编排智能体仅修改输入图与窗口参数。主路径结果作为“技术重要性”的客观锚点，供替代性分析中的地位转移指标 \(T_{AB}\) 使用。

#### 轨道 C：语义扩展与技术替代性分析

**目的**：主路径节点稀疏时，用语义相似专利扩容；进而量化路线间可替代性与替代成熟度。

**方法链条**：

1. **预筛**：本地小模型（如 `bge-small`）对摘要做余弦相似度，top-\(k\) ∪ 阈值并集，控制候选规模；
2. **精判**：大模型 API 逐对打分，输出 `{score, verdict, reason}`，形成可引用的相似理由；
3. **归属**：贪心唯一归属到最优（时期, 路径），并做阈值敏感性分析；
4. **可替代性**：在知识图谱或结构化属性上计算功能相似度 \(F_{AB}\)、场景相似度 \(C_{AB}\)、原理差异度 \(H_{AB}\)，综合  
   \(S_{AB}=w_1F_{AB}+w_2C_{AB}+w_3H_{AB}\)；
5. **替代趋势**：相对增长优势 \(G_{AB}\) 与主路径地位转移 \(T_{AB}\)，合成替代成熟度 \(M_{AB}\)；必要时计算国外路线安全暴露度等指标。

**封装形态**：

| 步骤 | 封装 | 算力 | 理由 |
|------|------|------|------|
| 嵌入预筛 | 固定程序 + 本地小模型 | 本地 | 高召回、低成本、可缓存向量 |
| LLM 精判 | Tool + 系统提示词 | 大模型 API | 需要可解释的语义理由，服务论文抽查 |
| \(S_{AB}/G_{AB}/T_{AB}/M_{AB}\) | 固定程序 | 本地 | 公式透明，便于敏感性与稳健性实验 |
| 图谱实体抽取（功能/场景/原理） | Skill + LLM / 规则混合 | 混合 | 开放信息抽取适合模型；schema 由程序约束 |

### 4.2 “四种执行形态”总览

| 形态 | 何时使用 | 示例 |
|------|----------|------|
| **固定程序（改输入即可）** | 算法成熟、需严格复现 | SPC、Key-Route、UMAP、K-means、指标公式 |
| **Skill（编程智能体按规范改写/生成脚本）** | 源站改版、新字段映射、临时可视化定制 | CNKI 导出适配器、新政策站点爬虫、Draw.io 布局脚本 |
| **本地小模型** | 大规模预筛、嵌入、轻量分类 | bge-small、本地 BTM、可选本地嵌入服务 |
| **大模型 API** | 关键词抽取、语义精判、冲突消解叙述、报告生成 | 关键词 Agent、相似度精判、战略顾问综述 |

这种分工使论文可以明确声称：**定量主干可复核，语义环节可审计（保留 prompt、score、reason），而非黑箱端到端生成。**

## 5. L3 多智能体协同解释与可视化层

L2 产出的是“证据”，L3 负责把证据提升为“情报判断”。系统设置角色化智能体，在共享知识库与统一证据对象上协作。

### 5.1 角色智能体（系统提示词限定）

| 智能体 | 职责边界 | 主要读取的 L2 产物 | 输出 |
|--------|----------|--------------------|------|
| **技术评估智能体** | 可行性、创新性、成熟度、技术风险 | 主题簇、主路径节点、c-TF-IDF | 技术维度评分与依据 |
| **经济价值智能体** | 产业化潜力、投入产出、经济风险 | 专利增长、同族/法律状态（若有） | 经济维度判断 |
| **市场潜力智能体** | 需求、竞争格局、增长空间 | 主题热度、政策注意力（Overton） | 市场维度判断 |
| **法律合规智能体** | IP 风险、法规约束、合规环境 | 北大法宝/政策文本、权利人属性 | 合规风险清单 |
| **战略顾问智能体** | 长期路线、资源配置、创新路径 | 全部维度 + 主路径演化 | 综合战略建议 |
| **前沿研判智能体** | 前沿类型判别与跨源一致性 | 前沿指标体系输出、论文—专利—政策对齐 | 前沿结论与证据表 |
| **替代性研判智能体** | \(S/M\) 态势分级与叙事 | 相似度表、\(S_{AB}\)、\(M_{AB}\)、路径地位 | 替代风险研判 |
| **可视化智能体** | 图稿生成与修订 | 网络、路径、聚类、指标 | Draw.io / 图像 / 图注 |

五维价值评估智能体可与前沿/替代研判智能体并行：前者回答“值不值得、风险在哪”，后者回答“是不是前沿、会不会被替代”。

### 5.2 协作与冲突消解

1. 各智能体独立产出带**证据指针**的结构化判断（指向具体专利号、主题 ID、路径 ID、指标值）；
2. **仲裁机制**检测逻辑冲突（例如：技术评估称“高度成熟”，而主路径地位持续下降且 \(M_{AB}\) 显示强替代）；
3. 冲突进入复算或降权：或触发 L2 敏感性分析，或在报告中并陈分歧并给出置信度；
4. 战略顾问在消解后生成**价值解释报告**，绑定最优权重组合（可由权重实验预设）。

消融实验（去掉某一智能体）与异质性实验（不同模型/提示词）用于论证协作增益，对应论文中的稳健性章节。

### 5.3 结果呈现的多通道可视化

| 呈现需求 | 通道 | 说明 |
|----------|------|------|
| 研究框架、系统架构、流程图 | **Draw.io MCP** | 生成可编辑 `.drawio`，便于论文修订 |
| 引文网络、主路径、时间窗演化 | **Python 固定绑图程序** → 可视化智能体润色 | 坐标与边权由程序保证正确；智能体只改样式与标注 |
| 概念示意、封面级示意图 | **文生图大模型** | 不承担定量精度，仅服务传播与章节导图 |
| 指标对比、敏感性表 | Python（matplotlib/plotly） | 数据驱动，禁止模型手绘数值 |

可视化智能体的系统约束：**不得改写底层数值；只能调整视觉编码与图注措辞。** 该约束由 Hook 在导出前校验（图中数字与数据文件哈希一致）。

## 6. 运行时资产：Agent / Skill / Tool / MCP / Hook 如何咬合

为使“多智能体系统”在论文中可检验、在工程上可扩展，系统将能力显式注册为五类资产。

### 6.1 资产分层

| 资产类型 | 含义 | 示例 |
|----------|------|------|
| **Agent** | 带角色系统提示词的决策单元 | 数据采集、技术评估、替代性研判、可视化 |
| **Skill** | 可被编程智能体加载的任务规范与脚手架 | “适配新政策站点爬虫”“为新 IPC 子集重跑主路径窗口” |
| **Tool** | 已实现、签名稳定的函数/脚本入口 | `spc_compute`、`semantic_prescreen`、`bigquery_patents` |
| **MCP** | 对外协议化能力 | Draw.io MCP、文献库 MCP、向量库 MCP |
| **Hook** | 事件驱动的强制检查与副作用 | 输出 JSON schema 校验、许可证检查、图数一致性、断点续跑 |

### 6.2 一次典型任务的协作叙事

以“某领域技术替代风险与前沿主题联合研判”为例：

1. **用户**给出领域关键词、时间窗与研究问题；
2. **编排智能体**解析意图，生成任务图（DAG）；
3. **数据采集智能体**并行调用：OpenAlex API、BigQuery 专利 SQL、Overton API；对 CNKI/法宝触发模拟点击或提示用户上传；
4. Hook `on_ingest_complete` 校验字段与去重率；
5. **分析编排**启动轨道 B（主路径固定程序）与轨道 A（向量化—聚类固定程序）；
6. 轨道 C：本地 bge 预筛 Tool → LLM 精判 Tool（断点续跑 Hook）→ 替代性公式 Tool；
7. **前沿研判 / 替代性研判 / 五维价值智能体**读取统一证据对象，并行生成维度结论；
8. **冲突消解**后，**可视化智能体**调用 Draw.io MCP 输出框架图，调用 Python 图结果生成主路径演化图，必要时用文生图生成章节概念图；
9. Hook `on_report_export` 检查所有断言是否带证据指针，生成可插入论文的方法—结果叙述草稿。

该叙事强调：**智能体负责分工与解释，工具负责计算与接入，Hooks 负责科学伦理与可复现底线。**

## 8. 实验与验证逻辑（系统层面对应论文实验）

系统方案同时支撑论文常见的实验叙事：

1. **性能实验**：量化各 Agent/模型在标注子集上的判别一致性；
2. **对比实验**：规则匹配 vs 语义匹配、单路径 vs Key-Route、仅专利 vs 论文—专利—政策三角；
3. **权重实验**：价值维度与 \(w_1,w_2,w_3\) 的动态组合；
4. **消融实验**：移除某一 Agent 或某一轨道，观察结论漂移；
5. **迁移与增强实验**：换领域子集、加噪声文本，检验稳健性。

这些实验在系统中表现为**同一 DAG 下的配置切换**，而不是另起一套脚本，从而强化“平台化方法”的说服力。

## 9. 结语：可写入论文的概括性表述

> 本文构建的多智能体情报分析系统，以科学—政策—技术多源数据为输入，在采集层按数据源特性分别采用 API、SQL 仓询、爬虫、模拟点击、批量下载与用户导入；在分析层将主路径识别、多特征主题发现、语义预筛与替代性指标等确定性方法固化为可复现程序与本地小模型流水线，而将关键词抽取、语义精判与跨维解释配置为提示词约束的智能体与大模型工具；在解释与呈现层通过多角色智能体协作、冲突消解与 Draw.io/程序绑图/文生图多通道可视化，形成从证据到结论的闭环。该设计使专利数据挖掘、技术替代性分析与前沿技术研判能够在同一方法论框架下协同完成，并保持计算过程可复核、语义判断可审计、情报叙事可验证。
