# 语义相似度匹配 — 设计文档（修订版）

日期：2026-08-06
项目：TRAE 多轨道（BCI 专利引文网络论文）
状态：已获用户批准（2026-08-06，三轮确认）

## 1. 背景与动机

导师质疑"主路径拼接文本做语义匹配"不合理（语义稀释/粒度错位/拓扑≠语义）；并建议"用提示工程让大模型直接判断两段摘要的语义相似度"。用户拍板：**从主路径重新出发，bge-small 余弦预筛 → DeepSeek LLM 逐对精判打分**。

核心约束（用户明确）：老师反馈规则匹配结果 1245 条"太少"，要求**尽量都筛出来合并到主路径**（高召回优先）。

## 2. 已确认决策（用户拍板）

| 决策点 | 选择 |
|---|---|
| 预筛器 | `bge-small-zh-v1.5` 余弦（本地 sentence-transformers；top-200 ∪ cos>0.4 并集） |
| LLM 精判 | DeepSeek `deepseek-v4-flash`，逐对打分，输出 {score 0-1, 判定, 相似理由} |
| 阈值策略 | 跑完看分数分布，输出 0.4-0.7 敏感性表；默认先按 0.55 出结果，最终档位用户/老师挑 |
| 唯一归属 | 全局贪心：每专利只归入 LLM score 最高的 (时期,路径)，过阈值才并入 |
| 每路径上限 | K=300（放宽，配合"尽量都筛出来"） |
| 与规则匹配关系 | 新结果为主数据集；规则匹配（1245 条）保留为对照，报告给出两方法重叠数 |
| 数据源 | `merged_patent_info.csv`（31650 有中文摘要）+ `主路径识别/outputs/window_*_paths_all.csv` top3 路径 internal 节点（179 篇） |
| 路径自身成员 | 排除（179 篇原始成员不参与"并入"） |

## 3. 流程

```
Step 1 数据准备（复用 路径概括与拓展/scripts/data_loader）
   候选专利 31650（pub, 摘要_中文, 元数据）
   路径专利 179 篇（period, path_id, pub, 摘要_中文）— 按时期分 15 组

Step 2 预筛（embedding 余弦，本地）
   bge-small-zh-v1.5 编码 31650+179 → 向量缓存 outputs/embedding_cache/*.npy
   余弦矩阵 31650×179（numpy，秒级）
   每路径候选 = 余弦 top-200 ∪ cos>0.4；排除路径自身成员
   → 预筛候选表（约 3000-6000 对）

Step 3 LLM 精判（DeepSeek，逐对）
   prompt：路径专利摘要 + 候选专利摘要 → LLM 输出 JSON
     {"score": 0-1, "verdict": "相似/不相似", "reason": "相似理由"}
   断点续跑：已打分的对跳过（基于结果 jsonl 文件）
   重试 3 次指数退避；3000-6000 对 ≈ 4-10 小时后台

Step 4 归属
   LLM score > 阈值（默认 0.55）→ 每专利贪心取最高分 (时期,路径)
   每路径并入 ≤ 300；标记：最相似路径专利 pub + 预筛cos + LLM score + reason

Step 5 输出（新建 语义相似度匹配/ 文件夹）
   outputs/semantic_assignments.csv   归属表（含相似理由，论文可直接引用）
   outputs/semantic_scores.jsonl      LLM 逐对原始打分（可复现）
   outputs/semantic_report.md         并入统计 + 阈值敏感性表(0.4-0.7) + 抽查
                                      + 与规则匹配(1245)重叠对照
   outputs/embedding_cache/*.npy      向量缓存（重跑秒级）
```

## 4. LLM prompt 设计（关键）

```
系统：你是专利语义相似度评估专家。基于两段专利摘要判断它们的技术语义相似度。
用户：
【路径专利】{公开号}：{摘要}
【候选专利】{公开号}：{摘要}
请判断两者技术语义相似程度，输出严格 JSON：
{"score": 0.0-1.0, "verdict": "相似/不相似", "reason": "不超过 50 字，说明相似的技术点"}
评分标准：技术功能/技术原理/应用场景/解决问题 越重合分越高；
仅属同一大领域（如都做脑电）但具体技术不同，score ≤ 0.5。
```

## 5. 计算量与成本

- 预筛：编码 CPU 3-8 分钟（一次，缓存后秒级）；矩阵秒级
- LLM：3000-6000 对 × 4-6 秒 ≈ 4-10 小时（后台，断点续跑）；token ≈ 1500-3000 万，flash 成本几十元
- 内存 < 4GB

## 6. 测试

1. 单测：预筛逻辑（top-200 ∪ cos>0.4、排除自身成员）、LLM prompt 构造、JSON 解析（含容错）、贪心唯一归属、敏感性表、重叠统计
2. 集成：小批量（2 个时期）跑通 → 全量后台
3. 抽查：并入专利与 LLM reason 人工核对合理性

## 7. 数量预期与论文衔接

预筛池 3000-6000 对；按 0.55 阈值预计每路径 50-200、总量 1500-4000（敏感性表 0.4-0.7 覆盖 500-8000 档）。semantic_assignments.csv 为论文第二步主数据集；与规则匹配结果的重叠/差异分析进论文稳健性部分。
