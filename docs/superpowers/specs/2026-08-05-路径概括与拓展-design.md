# 路径概括与拓展 — 设计文档

日期：2026-08-05
项目：TRAE 多轨道（BCI 专利引文网络论文）
状态：已获用户批准（2026-08-05）

## 1. 背景与目标

论文（见 `匹配_extracted/全文思路.md`）第二步需要"以语义相似度在全数据集筛选与主路径专利高度相似的专利，合并两类专利搭建研究数据集"。

本流程实现该步骤：对每个研究时期的 top-3 主路径，用 LLM 从摘要中概括出多维特征（关键词化），再对全数据集 7 万余条专利摘要做关键词匹配，把相似专利并入对应路径，形成各路径的扩展专利集合，供后续知识图谱构建与技术替代风险计算使用。

## 2. 已确认的决策（用户拍板）

| 决策点 | 选择 | 理由 |
|---|---|---|
| LLM | DeepSeek API（deepseek-chat） | 用户持有 key；中文概括质量好；无官方 embedding API，故匹配不走向量 |
| 匹配方式 | 纯关键词/正则匹配 | 零额外依赖、结果可追溯（可指出命中哪个关键词）、阈值可调控制规模 |
| 概括架构 | 方案2：时期级概括 + 两段式匹配 | 同一时期 3 条路径节点重叠 ≤70%，独立概括会特征雷同导致随机归属；时期级概括输出"整体特征+每路径差异化特征"解决归属歧义，且 5 次调用成本最低 |
| 归属规则 | 全局贪心唯一归属 | 每专利只保留得分最高的 (时期,路径)；防止一个专利并入多个时期多条路径 |
| 时期范围 | 5 个时期（2000-2005/2000-2010/2000-2015/2000-2020/2000-2026）× top3 路径 = 15 条路径 | 对齐论文研究分段；pre2000 萌芽期不纳入 |
| 申请日限制 | 不限制并入专利的申请日 | 全局贪心自然分配；报告标注申请日供论文分析 |

## 3. 输入数据

- `主路径识别/outputs/window_{2000_2005|2000_2010|2000_2015|2000_2020|2000_2026}_paths_all.csv`
  - 每窗口含 rank_by_spc、total_spc、node_count、internal_nodes、stage、node_sequence（"A → B → C"）等列
  - 取 rank_by_spc = 1..3 的三条路径；node_sequence 解析出节点（规范化公开号）
- `merged_patent_info.csv`（31899 行，引文管道全量 CSV 版；含 app_year/country 增强列）
  - 关键列：公开号（已补零规范）、摘要（英文原文为主）、摘要_中文（翻译为中文，优先用于匹配）、数据来源（BCI/incoPat）、申请日、公开日
  - 路径节点命中率抽查（2000-2010 路径1）：11/15 命中，外部节点（external_nodes）无元数据，跳过
- DeepSeek API：`DEEPSEEK_API_KEY` 环境变量

## 4. 处理流程

### Step 1 — 路径摘要提取（本地）

1. 对每时期每路径：解析 node_sequence → 节点列表
2. 规范化公开号（去连字符、大写）后在 merged_all 中匹配（沿用项目规范：US A 类补零）
3. 取每条专利的**中文摘要文本**，规则：
   - "摘要_中文"列非空 → 用它
   - 否则"摘要"列含 CJK 字符 → 用它（本身是中文）
   - 否则 → 跳过该专利（报告统计跳过数）
4. 输出每时期 3 条路径的（路径ID, 节点, 标题, 摘要）清单，供 Step 2 用

### Step 2 — 时期级 LLM 概括（5 次 API 调用）

每时期一次调用，prompt 包含该时期 3 条路径的全部内部节点摘要（各路径 7-13 条，单 prompt 约 2-4 万 token，deepseek-chat 可处理），并要求输出**严格 JSON**：

```json
{
  "period": "2000_2010",
  "overall": {
    "功能主线":    {"描述": "...", "关键词_中": [...8-15], "关键词_英": [...]},
    "解决问题":    {"描述": "...", "关键词_中": [...], "关键词_英": [...]},
    "应用场景":    {"描述": "...", "关键词_中": [...], "关键词_英": [...]},
    "技术原理":    {"描述": "...", "关键词_中": [...], "关键词_英": [...]}
  },
  "paths": [
    {"path_id": 1, "差异化特征": {
      "功能侧重": {"描述": "...", "关键词_中": [...], "关键词_英": [...]},
      "问题侧重": {"描述": "...", "关键词_中": [...], "关键词_英": [...]},
      "场景侧重": {"描述": "...", "关键词_中": [...], "关键词_英": [...]},
      "原理差异": {"描述": "...", "关键词_中": [...], "关键词_英": [...]}
    }},
    {"path_id": 2, ...}, {"path_id": 3, ...}
  ]
}
```

要求：关键词为技术短语（非句子）、中英对照、与路径摘要强相关、避免与另两条路径的差异化特征重叠（LLM 需看到全部 3 条路径的摘要后比较输出）。

### Step 3 — 全数据集关键词匹配（本地）

对 72583 条专利中所有有摘要文本者（约 7 万）：

1. **时期整体得分** `S_period = Σ w_i × hit_i / Σ w_i`
   - 维度权重：功能 0.35、解决问题 0.30、应用场景 0.20、技术原理 0.15（对齐论文三大相似度指标+问题维度）
   - `hit_i` = 该维度命中关键词数（封顶 3，防一词多命中爆分）
2. **路径差异化得分** `S_path(p) = Σ w_i × hit_i(path p) / Σ w_i`（对时期内的 3 条路径各算）
3. 匹配规则：
   - 中文关键词：子串包含匹配（`in` / re.search）
   - 英文关键词：正则转义 + 词边界（`\b`）包含匹配（对翻译列中保留的英文术语同样生效）
   - 无摘要文本的专利跳过

### Step 4 — 全局贪心唯一归属

1. 收集全部（专利, 时期, 路径, S_period, S_path）候选
2. 对每专利取 S_path 最高的 (时期, 路径)；若 S_period ≥ θ₁ 且 S_path ≥ θ₂ → 归属该路径；否则不归属
3. 每路径并入上限 K=100：超过上限时只保留该路径 S_path 最高的 100 条
4. 阈值默认：θ₁=0.3、θ₂=0.3（可调）

### Step 5 — 报告

`extension_report.md`：
- 每时期每路径：并入数、中位得分、并入专利的申请日分布（标注晚于时期终点的数量与比例）
- 阈值敏感性表：θ ∈ {0.2, 0.25, 0.3, 0.35, 0.4} 的并入量，供选档
- 每条路径抽查 5 条并入专利的摘要与命中关键词明细（可人工验证合理性）
- 统计：有摘要总数、被跳过数、归属率

## 5. 输出产物（新建 `路径概括与拓展/` 文件夹）

```
路径概括与拓展/
├─ prompts/period_{label}_prompt.txt      5 个 prompt 存档（可复现）
├─ outputs/
│  ├─ period_{label}_summary.json         每时期 LLM 特征概括（原始）
│  ├─ period_{label}_summary.md           可读版（维度描述+关键词表，可进论文附录）
│  ├─ matching_scores.csv                 候选得分矩阵（仅过时期门槛的专利×3路径，含 S_period/S_path）
│  ├─ assignments.csv                     全局归属表（专利→时期-路径，得分、命中维度、申请日）
│  ├─ extension_report.md                 统计报告（含敏感性表、抽查样例）
│  └─ extension_results.xlsx              合并表（归属+摘要+元数据，供下游知识图谱使用）
└─ logs/                                   API 调用日志（重试、失败记录）
```

## 6. 误差处理

- API 失败：重试 3 次 + 指数退避（1s/2s/4s）；连续失败则终止并保留已产出（断点续跑：已成功的时期不再重复调用）
- JSON 解析失败：自动重试并要求"仅输出 JSON 代码块"
- 摘要缺失/节点未命中：跳过并计入报告统计
- 编码：所有输出文件 UTF-8；xlsx 写入走 pandas

## 7. 测试策略

1. 单测：关键词命中（中文子串/英文词边界）、得分归一化、贪心唯一性（构造 3 专利 2 时期小样例断言）
2. 集成：跑通 2000-2005 单时期端到端（含 1 次真实 LLM 调用），人工检查概括质量与并入专利合理性（抽查 5-10 条摘要）
3. 全量：5 时期全跑，检查膨胀控制（每路径 ≤ K 且阈值敏感性表合理）
